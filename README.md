# ブロック表示チェッカー

共通の商品紹介ブロックが、各販売サイトのCSSの影響でどう表示されるかを確認するツールです。
ビルド不要の静的ファイルだけで動きます。

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `index.html` | ツール本体（通常は編集不要） |
| `sites.js` | 確認対象サイトの設定。サイトの追加・CSSのURL変更はここだけ |
| `base-reset.css` | 「基準」にだけ当てる、全サイト共通のリセット |

## 公開手順（GitHub Pages / 社内限定）

1. 組織内にリポジトリを作成し、上の3ファイルをルートに置いて push する
2. リポジトリの Settings → Pages で、Source を「Deploy from a branch」、ブランチを `main`・フォルダを `/ (root)` にする
3. 同じ Pages 設定画面で公開範囲（Visibility）を Private にする
   - Enterprise Cloud の private Pages なので、リポジトリの閲覧権限を持つメンバーだけがアクセスできます
4. 表示された URL をチームに共有する

ローカルで試すときは、フォルダで `npx serve` や `python3 -m http.server` を実行してブラウザで開いてください。

## sites.js の書き方

```js
{
  id: 'a',                       // 英数字。共有リンクに使われる
  name: 'Aサイト',                // ボタンの表示名
  css: ['https://.../style.css'], // 本番の head と同じ順番で
  headHtml: '',                  // Google Fonts の link など（任意）
  bodyClass: 'page-product',     // 本番 body の class（任意）
  wrapper: '<main class="l-main"><article class="entry">{{content}}</article></main>',
  baseUrl: 'https://a-site.example.com/' // ブロック内の相対パスの基準（任意）
}
```

`wrapper` はできるだけ本番の親要素を再現してください。`.entry p { ... }` のような親起点のセレクタによる干渉は、ラッパーがないと再現されません。

## 使い方

- 左の入力欄にブロックのHTML（`<style>` を含む）を貼ると、自動でプレビューが更新されます
- 「基準（共通リセットのみ）」は、ブロック自身のCSSに、全サイトで共通して効いているリセット（`base-reset.css`）だけを加えた表示です。各サイトのボタンの数字は、基準と計算スタイルが違う要素の数です
  - 見出しや段落の margin など「どのサイトでも同じようにリセットされる差」は出なくなり、サイト固有のCSSによる差だけが残ります
  - サイトを追加・変更したときは、そのサイトでも同じリセットが効いているか確認し、共通でなくなったルールは `base-reset.css` から外してください
- 下の差分パネルで、どの要素のどのプロパティが変わっているかを確認できます。「プレビューで場所を表示」で該当要素が赤枠で示されます
- 「共有リンクをコピー」で、入力中のコードごとURLにして共有できます（コードはURLの # 以降に入るので、サーバーには送信されません）
- 入力内容はブラウザの `localStorage`（キー: `block-preview-state-v1`）に保存されるので、リロードしても消えません
  - そのため `index.html` 側のデフォルトのブロックHTMLを変更しても、保存済みの内容が優先されて反映されないことがあります。その場合はブラウザの開発者ツールのConsoleで次を実行してからリロードしてください（またはシークレットウィンドウで開く）
    ```js
    localStorage.removeItem('block-preview-state-v1');
    ```

## 制約

- 他ドメインのCSSは、ブラウザの仕様で読み込み成否を判定できません。「CSSを読み込めません」の警告は同一ドメインのCSSでのみ表示されます。差分が0件で違和感があるときは、sites.js のURLを直接ブラウザで開いて確認してください
- Webフォントは、配信元がCORSを許可していないと読み込まれず、本番と見た目が変わることがあります
- 本番サイトのJavaScriptによるDOM変更は、「JavaScriptを実行する」をオンにして `headHtml` にscriptを書いた場合のみ再現されます
- 差分は「基準」と各サイトで同じ表示幅のときに比較しています
